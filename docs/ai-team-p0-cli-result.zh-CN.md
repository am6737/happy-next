## 实现

- P1 Leader 仅在团队根 execution 获得 `ai_team_delegate` MCP 工具。daemon 私有 loopback 代理保留账号认证，并将当前 taskId/dispatchToken 绑定到随机 execution 能力；桥的 MCP 白名单只有该工具，Codex 对它使用官方支持的逐工具 `approval_mode="approve"`，全局仍为 `approval=never`、`workspace-write`。代理随 execution 结束撤销，server 再核验团队、成员、预算与 DAG。
- Aggregate 在独立 workspace 持锁后从账号认证的 run/tasks API 取得依赖 taskKey，定位本机登记的两个以上已完成成员 worktree；核验同 Git common dir、同 base、干净状态与 HEAD 后禁 hooks cherry-pick。冲突保留现场并上报失败；模型完成后再验证成员 patch 和每个改动文件的提交字节。成员/aggregate SHA 组成 `integrationProof` 随 durable finish 入队及发送；server 已持久化并通过独立只读 RPC 验证后才完成任务。
- 运行中 Codex steering 注册 `${machineId}:orchestrator-steer`：验证 execution 与 dispatchToken，只在已有 session ID 且未取消/超时时接收；信号中断当前 one-shot，再以同一 session/worktree/租约 resume。one-shot 现在向模型子进程转发 TERM/INT，并在超时后 KILL。其他 provider 对运行中 steering 明确拒绝。
- 纯 HTTP Responses 仅接受 `status=completed`、单一完成消息且无 function/tool 项；Chat 仅接受单一 `finish_reason=stop` 且无 tool/function calls。最终回复按 UTF-8 65,536 字节限制，失败或未完成 JSON 不产生可消费 `finalResponse`。
- Codex one-shot 使用 `exec --json`，daemon 仅接受完成回合中的最终 `agent_message` 作为 `finalResponse` 和用户可见 `outputText`，记录 session ID；命令事件、banner、usage 和 stderr 不拼入聊天。Claude/Gemini 仅取其 JSON 结果字段；无有效最终文本的成功退出改为失败。JSONL 单行超过上限时失败关闭并释放缓冲。错误诊断脱敏。
- 在线 machine 注册 `${machineId}:ai-structured-model` RPC。CLI 从当前 Codex provider/model 配置和本机认证读取纯 HTTP `responses` 或 `chat/completions` 路径，强制 `tools: []` 与 `tool_choice: "none"`，限制输入、响应、超时并在 daemon 退出时取消请求。认证不传 server；无可支持的 HTTP provider 时返回 `PURE_MODEL_UNAVAILABLE`，不会退到 CLI/MCP。
- Orchestrator one-shot 子进程继承与普通 daemon 会话相同的兼容活动 profile 环境变量；派发专用环境字段仍由受信任 payload 覆盖。
- Workspace 创建与记录使用 `flock` 内核锁，锁文件 inode 保留。记录先原子写入，再执行 `git worktree add`；可恢复分支和 Git 注册已创建但目录缺失的中断状态。resume 核对 task、仓库真实路径、Git common directory、分支及基准 commit；新 task 不复用旧 workspace。
- 每个 workspace 的执行租约覆盖 dispatch 后的模型进程和 finish 入队。持锁进程异常退出时终止模型并上报 `WORKSPACE_LEASE_LOST`。同机跨进程冲突失败关闭；缺少 Linux `flock` 时明确失败。
- Headless `approval` 拒绝启动，人工审批通道尚未实现；Gemini `read_only` 因不能保证只读而拒绝。Codex 在 `workspace-write` 沙箱内改文件。真实测试发现该沙箱不允许写 Git worktree 的共享 `.git` 元数据；因此 daemon 对成功的 `guarded_auto` 执行，在仍持有任务租约并重新验证 workspace 身份后，仅在隔离 task 分支上暂存和本地提交改动，禁用 Git hooks；提交失败则上报 failed。不会推送、建 PR 或合并。
- Finish report 在发送前写入按 server URL 和账号公钥隔离的私有队列；原子写入、内核锁防止并发 flush、不同 dispatch owner 不能覆盖。坏 JSON/永久 4xx 不阻塞后续记录，成功响应后才删除；daemon 启动及每 15 秒重试。准备 workspace 和同步 spawn 失败也进入队列。
- GC 只有显式 `previewExecutionWorkspaceGc()` dry-run：调用方须提供终态验收 task 集合和保留期，候选需身份有效、工作树干净、未被租约占用。没有自动删除。
