结果 exit **1**，关键输出 `PUBLIC_HTTP_FINISH_TENANT_EVIDENCE submit=200 finish=200 foreignMessages=1`，而断言期望 B 会话消息数为 0。与主会话直接 DB 构造 metadata 的已有失败相比，此脚本通过认证的 **public `/v1/orchestrator/submit` HTTP** 创建 A 的 Run，随后从 DB 核对保存了 B 的 `conversationId/aiAgentId`；只对 A 自有的 Run/Task 在 DB 建 running execution 和合法 token，再以 **public `/executions/:id/finish` HTTP** 完成。finish 将 A 的最终文本写入 B 的会话。执行未启动 scheduler/daemon/model，也未注册 mock RPC；本脚本的 execution 状态由安全 fixture 构造，故它证明 public submit 输入到 finish 消费的权限链，而不证明真实 daemon dispatch。
