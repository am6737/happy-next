title: "自托管"
description: "部署你自己的 Happy Next 服务器，完全掌控你的数据。"
---

你可以托管自己的 Happy 服务器，而不是使用 `api.happy-next.com` 上的托管服务。这让你完全掌控自己的数据和基础设施。

Happy 支持两种模式：
- **托管（默认）** — 客户端开箱即用地使用 `https://api.happy-next.com`
- **自托管** — 使用 Docker Compose 运行你自己的 `happy-server`、`happy-voice` 和支持服务

## 环境要求

- **Docker + Docker Compose**
- **火山引擎 RTC 应用**（"AI 智能体"类型）— 用于语音功能
  - 你需要 `VOLC_RTC_APP_ID`、`VOLC_RTC_APP_KEY`，以及 IAM 密钥 `VOLC_ACCESS_KEY_ID`、`VOLC_SECRET_ACCESS_KEY`
- 语音所需的 **火山 / 豆包凭据**（如果使用语音功能）
  - 消息播报 TTS 使用 `VOLC_TTS_APP_ID`、`VOLC_TTS_TOKEN`；可选的 TTS 前文本清洗使用 `ARK_API_KEY`（完整清单参见 `.env.example`）

## 快速开始

1. 克隆仓库：

```bash
git clone https://github.com/hitosea/happy-next.git
cd happy-next
```

2. 创建环境配置文件：

```bash
cp .env.example .env
```

3. 编辑 `.env` 并填写必需的值。至少需要：
   - `HANDY_MASTER_SECRET` — 生成一个 64 个字符以上的随机字符串
   - `POSTGRES_*` — 数据库凭据
   - `S3_*` — 或使用 MinIO 默认配置
   - `VOLC_RTC_*`、`VOLC_ACCESS_KEY_ID`/`VOLC_SECRET_ACCESS_KEY`、`VOICE_AUTH_SECRET` 和 `PUBLIC_VOICE_BASE_URL` — 如果使用语音功能

4. 启动服务栈：

```bash
docker-compose up -d
```

   首次启动时，`happy-server` 会自动运行 `prisma migrate deploy`，`minio-init` 服务会自动创建存储桶并开启匿名下载——无需手动进行数据库或存储桶的初始化。

5. 在 `http://localhost:3030` 打开 Web 应用。

### 手动维护（可选）

数据库迁移和存储桶会自动完成，但你也可以在需要时手动重新执行：

```bash
# 重新应用数据库迁移
docker-compose exec happy-server yarn --cwd packages/happy-server prisma migrate deploy

# 重新创建 MinIO 存储桶（使用你的 S3_ACCESS_KEY / S3_SECRET_KEY 值）
docker-compose exec minio mc alias set local http://localhost:9000 "$S3_ACCESS_KEY" "$S3_SECRET_KEY"
docker-compose exec minio mc mb local/happy-server
docker-compose exec minio mc anonymous set download local/happy-server
```

## 服务

Docker Compose 服务栈包含：

| 服务 | 端口 | 描述 |
|---------|------|-------------|
| `happy-app` | 3030 | Web 应用（Nginx） |
| `happy-server` | 3031 | API 服务器（Node.js） |
| `happy-voice` | 3040 | 语音网关（Node.js） |
| `minio` | 3050 | S3 兼容文件存储 |
| `postgres` | 5432 | 数据库 |
| `redis` | 6379 | 缓存和 Socket.IO 适配器 |

## 连接 CLI

CLI 默认连接托管 API。对于自托管，设置环境变量：

```bash
HAPPY_SERVER_URL=http://localhost:3031 HAPPY_WEBAPP_URL=http://localhost:3030 happy
```

## 连接移动应用

- **开发构建：** 启动 Expo 时设置 `EXPO_PUBLIC_HAPPY_SERVER_URL`，或使用应用内的服务器设置界面
- **生产构建：** 使用应用内的服务器设置界面设置自定义服务器 URL

你只需配置一个**基础服务器 URL**。客户端在连接时会从该服务器的 `/v1/app-config` 获取真正的 API 与语音端点，因此你的 API 服务器和语音网关可以部署在不同主机上，而无需在应用里分别配置。为了让服务发现返回正确的公网地址，请在服务器上设置 `PUBLIC_API_BASE_URL`（以及语音配置）——参见[环境变量](/zh/advanced/env-vars)。

在应用中更换服务器会先校验 URL，然后将你登出，以便你对新服务器重新登录。一旦使用了自定义服务器，设置页会出现一个返回服务器界面的快捷入口。

## S3 / MinIO 说明

`S3_PUBLIC_URL` 必须可被客户端（浏览器和移动端）访问，而不仅仅是 Docker 容器。

- **本地：** MinIO 在 `http://localhost:3050` 暴露，因此 `S3_PUBLIC_URL=http://localhost:3050` 可以使用
- **远程：** 使用真实的 S3 兼容端点，并配置与你的 TLS/主机设置匹配的公共 URL

## 远程访问

如果从其他设备（局域网或互联网）访问，请避免硬编码 `localhost` URL：

- 将 Web 应用、API 和语音网关放在带 TLS 的域名后面
- 将 `EXPO_PUBLIC_HAPPY_SERVER_URL` 设置为公网 Web/API 来源
- 在服务器上设置 `PUBLIC_API_BASE_URL` 和 `PUBLIC_VOICE_BASE_URL`，让 `/v1/app-config` 返回正确的公网 API / 语音端点（对于 docker-compose，还需设置 `EXPO_PUBLIC_VOICE_TOOL_BRIDGE_BASE_URL`，以便网关能访问 `happy-server`）
- 将 `APP_URL` 设置为你的 Web 来源

## 故障排除

```bash
# 检查容器状态
docker-compose ps

# 查看日志
docker-compose logs -f happy-server
docker-compose logs -f happy-voice
```

验证主机上的端口：Web (3030)、API (3031)、Voice (3040)、MinIO (3050)。

完整的配置参考请参阅[环境变量](/zh/advanced/env-vars)。
